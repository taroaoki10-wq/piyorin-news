# ぴよりんニュース

ぴよりんの公式発表・プレスリリース・メディア記事を自動で集めて表示するページです。
GitHub Actions が1時間ごとに情報を集め、GitHub Pages で公開します。予定の読み取り・関連判定・ぴよのメモ作りに Claude API（Haiku）を少し使います。スマホでは、右下で待機しているマスコットの「ぴよ」を押すとチャットできます。

## しくみ

```
GitHub Actions（1時間ごと・毎時23分）
  └ scripts/fetch_news.py（7つの情報源を同時に取得）
      ├ ぴよりん公式サイト「お知らせ」
      ├ PR TIMES（ジェイアール東海フードサービス）
      ├ Googleニュース「ぴよりん」（関連度順・直近7日・直近1日）
      └ Bingニュース「ぴよりん」（関連度順・直近7日）
          ↓ 新しい記事だけ追記（同じ話題は「ほか◯件」にまとめる）
      docs/data/news.json
  └ scripts/extract_events.py
      公式記事とプレスリリース（PR TIMES）から販売期間・開催日を読み取り
        ・同じ話題の公式記事と PR TIMES、公式記事に載った PR TIMES のリンク先をまとめて読む
        ・本文だけを読む（投稿日・分類の札・関連記事の一覧の日付は読まない）
        ・日付のない記事 → 何もしない
        ・日付がある記事 → 日付まわりの抜粋だけをまとめて Claude API へ（キーが無いときはパターンで読む）
          ↓
      docs/data/events.json
  └ scripts/build_reader.py（リーダー用に元記事を保存）
  └ scripts/judge_relevance.py（ぴよりんと関係ある記事か判定）
  └ scripts/build_piyo.py（ぴよのメモとまとめを作り置き）
          ↓
      docs/data/piyo-memo.json・piyo-greeting.json
          ↓
GitHub Pages（docs/index.html、5分ごとに読み直し）→ Safari で表示
```

## 古い記事の保管

収集時は `news.json` と年別保管庫の両方を読み、重複を確認します。掲載日を確認したあとで新しい順に分け、最新500件を `news.json`、残りを `archive/YYYY.json` に保存します。500件を超えても記事を捨てません。保管庫を読めない場合は更新を止め、空の保管庫で上書きしません。

画面では最新記事を先に表示し、保管記事を取得できたら同じ一覧・検索に加えます。記事ID・URL・関連リンク・AI判定を保つため、ブックマークと非表示設定も引き継がれます。取得失敗時は表示中の保管記事を維持し、次の更新で再試行します。年別保管は記事情報が対象で、古い記事の本文キャッシュを永久保存する機能ではありません。本文がない場合は従来どおり元の記事へのリンクで読めます。

自動の予定抽出・AI判定・ぴよメモ作りは従来どおり最新500件を対象とします。

検証: `python3 -m unittest discover -s tests`、`node --test tests/*.test.cjs`。

## 写真ページの重複整理

公式サイトの記事の見出しは、一覧の見出しの要素から読みます（2026年9月末から、リンクの中に分類の札と「記事を見る」が入るため）。保存済みの見出しからも札と「記事を見る」を外すので、同じ話題の PR TIMES の記事と1つにまとまります。末尾の「｜Infoseekニュース」などの掲載サイト名、「HOME PR TIMES」のようなパンくず、ファッションプレスの写真ページ（「写真3/3｜」、`/news/gallery/`）も整理し、Googleニュースで途中まで切れた見出しは、前半が同じで日付が7日以内の記事にまとめます。同じ媒体の元記事があるときは、Googleニュース経由の同じ記事へのリンクを「ほか◯件」に入れません。まとめた記事のほかの掲載元は、リーダーの「ほか◯件の掲載元」から開けます。

写真番号・「画像・写真」などの見出し飾りを外し、同じ見出し、同じURL、対応媒体の記事IDで重複をまとめます。記事IDの照合対象はライブドア・ORICON・産経・AERA dot.です。未知の媒体の `/photo` を一律に削ったり、記事URLを推測して作ったりはしません。関連リンクに既にある記事も照合するため、写真の説明文や省略された見出しで再配信されても重複を抑えます。

公式・プレスを優先し、同じ分類では通常の記事を写真・コメントページより優先します。代表記事のIDとAI判定は維持し、判定がない場合だけ統合対象から引き継ぎます。統合した旧IDは `merged_ids`、元URLは同じ媒体のものも `related` に残します。URLで保存された既存ブックマークは変更せず、旧IDの非表示設定は代表IDも含めて最新の操作を採用します。同じ時刻の競合は非表示を優先します。

既存データも最新記事と年別保管庫を合わせて整理します。整理後が500件未満なら保管記事は `news.json` に戻ります。AIの再判定・メモ生成・外部API呼び出しはこの整理では行いません。

## 予定（カレンダー）の自動追加

`scripts/extract_events.py` が、公式サイトのお知らせとプレスリリース（PR TIMES）の記事を Claude API（`scripts/claude_events.py`、既定は Claude Haiku 4.5）に渡し、販売期間・開催日・キャンペーン期間などを予定として読み取って `docs/data/events.json` に追加します（`"auto": true` と、読んだ記事の ID の `"src"` が付きます）。1つの記事に日程が複数あれば、それぞれ別の予定になります。

- 公式サイトの記事には日付が書かれず「詳しくは下記URL」と PR TIMES へのリンクだけのことがあります。そのため、同じ話題としてまとめた公式記事と PR TIMES の記事、公式記事の本文に載った PR TIMES の記事を一緒に読みます。
- 読むのは本文だけです。公式サイトの投稿日・分類の札（店舗・限定商品など）、記事の下の「関連記事」の一覧（別の記事の日付が並ぶ）、PR TIMES の配信日時は読みません（以前はこれを予定の日付と取り違えることがありました）。
- 記事ごとに「読んだ元の組み合わせ」を `docs/data/state.json` に記録します。あとから PR TIMES の記事がまとまるなど元が増えたとき、または読み取り方を変えて `EXTRACT_VERSION` を上げたときは、直近120日の記事を読み直して、その記事の自動の予定を入れ替えます（1回の更新で20記事まで）。読み直して何も見つからなかったときは、前の予定を残します。読めない元があった記事は次の更新でもう一度読みます。
- 別々の記事から読んだ同じ予定（期間が同じで名前が似ている自動の予定）は1つにします。手で登録した予定は書き換えません。
- 手で登録した予定は Claude にも伝え、名前の言い方が違っても同じ商品・同じ催しで同じ期間の予定は出さないようにします。期間が同じで名前がほぼ同じ（2文字ずつの並びが6割以上重なる）自動の予定は外します（手の予定を残します）。「ドデ祭2026」と「ドデ祭2026 ぴよりん販売」のように、名前を含むだけの別の予定は残します。

- APIキーは GitHub の Settings → Secrets and variables → Actions に `ANTHROPIC_API_KEY` として登録します。
- キーが未登録のときは、見出しのパターンから日付を読み取る方法で動きます（予定の名前が長くなることがあります）。
- 使ったトークン数は Actions のログ（「Claude API 使用量」）に出ます。
- モデルを変えたいときは、ワークフローの env に `CLAUDE_MODEL` を追加します。

読み取りを間違えた予定は、`events.json` で直接直してください。直した予定から `"auto": true` を消すと、手で登録した予定として扱われます。予定を手で追加することもできます（ファイルを開いて鉛筆アイコン → 編集 → Commit changes）。

```json
{
 "id": "e-好きな英数字",
 "title": "予定の名前",
 "start": "2026-10-01",
 "end": "2026-10-04",
 "place": "場所",
 "kind": "sale",
 "url": "https://..."
}
```

`kind` は次のどれかです。

- `sale`：限定販売（黄）
- `event`：イベント（青）
- `campaign`：キャンペーン（緑）
- `release`：発売・受付開始（枠線）

## 関係ない記事の判定・削除

`scripts/judge_relevance.py` が、公式以外の記事（プレスリリース・メディア）がぴよりんに関係あるかを Claude（既定は Haiku 4.5）で判定し、`news.json` の各記事に `jg`（`ok`・`why`）を書き込みます。判定済みの記事は読み直しません（1回の更新で最大90件、新しい記事から）。

- 画面では、`ok: false` の記事はニュース一覧に出さず、「削除済み」に移します。「削除済み」から記事を読んだり「元に戻す」ことができます。
- 一覧の記事にカーソルを合わせると出るごみ箱ボタン（スマホは常に表示）や、リーダー右上のボタンで、手動でも削除できます。直後に「元に戻す」も押せます。
- 削除と元に戻した記録はブラウザ（localStorage `piyo-del`）に保存され、ブックマークの同期を設定していれば、同じ非公開 gist の `piyorin-hidden.json` に保存されて端末間で共有されます。
- 判定の基準を変えたときは `JUDGE_VERSION` を上げます。すべての記事をもう一度判定したいときは、Actions の「Run workflow」で `rejudge` にチェックを入れます。
- APIキー（`ANTHROPIC_API_KEY`）が無いときは判定せず、記事はそのまま表示されます。

## ぴよ（スマホでチャット）

スマホの幅（620px 以下）で見ると、右下でぴよが待機しています（まばたきします）。押すとぴよがチャットの位置へ滑って移動し、しまう（× か会話を下へ引く）と待機の位置へ滑って戻ります。PC の画面は変わりません。

ぴよを呼ぶ際、前回のあいさつから30分以上たった場合、または日本時間の日付が変わった場合は、まとめ・メモ・予定・記事・基本情報・天気を再取得し、新しくあいさつします。新しくあいさつするときは、前の会話の表示と記憶（直近5往復）を消し、最新のあいさつと候補から始めます。返事待ちの間は消さず、次に呼んだときへ持ち越します。30分未満で日付も変わっていないときは会話を残します。取得失敗時は既存のデータを保持しますが、古い天気は使わず、次の呼び出しで再試行します。取れなかった分（電波が弱くて天気が取れなかったときなど）を取り直すだけのときは、会話を消しません。天気は1.5秒だけ待ち、間に合わなければ天気なしであいさつします。

- 押すとぴよが出てきて、最初に「最近のぴよりんニュース」のまとめをつぶやきます。入力欄の上には質問の候補が並び、押すとその質問を送ります。
- 日時に関する候補は「〇〇はいつから？」と聞き直す形を避け、「〇〇について」と話題を選ぶ文言にします。保存済みの日時候補も表示時に整え、押した後の質問文も同じ文言にします。値段や場所などの候補と、回答を作る処理は保ちます。
- 最初はぴよりん情報の候補を表示し、質問すると、残りの候補を保ったまま右側へ別の質問を補充します。取得済みの基本情報・記事メモ・今日と明日の名古屋の天気に答えがあるものだけを使い、同じ会話で聞いた候補は繰り返しません。候補の補充にAI呼び出しや追加取得は使いません。普通のニュースは現在の公開版に収録されていないため候補に含めません。候補を使い切ったら数は減り、新しいあいさつで履歴と候補をリセットします。
- 「〇〇について」は、手元の知識に載っている話題の概要を答えるよう指示します。メモに「詳細は記事で確認」とあっても、概要を答えられるならその範囲で返します。話題の情報がない場合や、具体的に聞かれた項目の情報が足りない場合は、従来どおり「調べる」で追加確認します。
- 入力欄を押すとキーボードが出て、自由に質問できます。会話は吹き出しで残り、上へスクロールして遡れます。ぴよを出している間、裏のページは動かず、押しても反応しません。
- キーボード表示中だけ会話欄の高さを確保し、通常時の表示上限と上端をそろえます。全画面の固定要素を基準に実際の下端との差を測り、ぴよ・質問候補・入力欄はそのまま残します。キーボードを閉じると高さの固定を解除します。通常時の会話の高さは内容に合わせ、短い会話で背景マスクを上まで広げません。実iPhoneでの解消は未確認です。
- 表示が崩れる場合は、チャットを開いて、ぴよの左側の灰色の余白を1.5秒長押しすると「表示診断1」を開けます。キーボードを開いて閉じ、「結果をコピー」で寸法をコピーしてCodexへ貼り付けます。会話・入力文・キー・保存情報は読み取らず、外部送信もしません。「終了」で診断を閉じます。
- iPhoneのホーム画面起動では、ステータスバーを透過設定にしてページを最上部まで描画し、チャット中の半透明マスクもダイナミックアイランド周辺まで届くようにします。通常画面でも上端は透過扱いになります。時刻や操作部分に重ならないための安全領域の余白は維持します。端末・iOSによる反映は実機確認が必要です。
- 会話のスクロールバーを画面の右端に寄せ、明暗それぞれで薄い色にしています。会話欄は従来より最大96px上へ広げ、上側の安全領域と16pxの余白を残せる範囲に制限します。吹き出し・ぴよ・候補・入力欄の横位置、上端18pxのフェードは保ちます。
- キーボードを閉じた後の高さ・下余白が初回へ戻らない問題は、過去にCodexが解決できなかった記録を保持しています。最新のユーザー報告は「ぴよの高さのバグ直ったかも」で、改善した可能性あり・再確認待ちです。また、キーボード使用後にチャットを閉じてメイン画面をスクロールすると、待機中のぴよがスクロールに合わせて動く別の不具合は未解決です。
- あいさつの出典は、本文を最後まで表示したあとに文字全体がふわっと現れます。出典自体は文字送りにせず、動きを減らす設定では本文完了後にそのまま表示します。
- 待っている間はまばたきし、タップすると手を振ります。入力欄の右の × でしまいます。会話をいちばん上まで遡った状態で下に引っ張って離しても、しまえます。
- まとめと質問の候補は `scripts/build_piyo.py` が自動更新のときに作り置きします（メモか予定が変わったとき・日付が変わったときだけ作り直すので、呼ぶたびの料金はかかりません）。
- 質問の答えは、ページが Claude API（Haiku 4.5）を直接呼んで作ります。ぴよりんの基本情報（`piyo-basics.json`）とぴよメモ（`piyo-memo.json`）と予定（`events.json`）を渡すので、たいていは Web 検索なしで答えます。1回の質問で 1〜3 円ほど、「調べる」を押すと 5 円ほどです。
- メモと予定だけで答えられないときは、ぴよが「記事をくわしく読まないと分からないぴよ。調べる？」「Web で調べる？」と聞きます。「調べる」を押したときだけ、記事の本文（最大3件）を足して聞き直すか、Web 検索（最大3回）を使います。記事は、ほとんどの記事に出てくる言葉（「ぴよりん」など）を手がかりにせず、直近60日の記事と公式・プレスリリースを少し優先し、同じ見出しは1つだけ選びます。まとめた公式・PR TIMES の本文も一緒に読みます。Web 検索が終わりきらなかった答えには「調べきれなかった」と添えます。
- 返事の中の URL は、空白・かっこ・句読点で区切ってリンクにします（「[文字](URL)」の形は文字をリンクにします）。API キーが使えない（401）ときだけキーを入れ直してもらい、権限の不足（403）ではキーを消しません。
- はじめて質問すると、Claude の API キーを入れる画面が出ます（[コンソール](https://platform.claude.com/settings/keys)で作ります）。キーはその端末のブラウザ（localStorage `piyo-key`）にだけ保存されます。解除は「ブックマーク」タブの下から。使いすぎが心配なら、コンソールで月の使用額の上限を決めておきます。
- Web 検索は、コンソールの設定で Web 検索が許可されていないと使えません。
- 名古屋の天気は、ぴよを呼んだときにページが [Open-Meteo](https://open-meteo.com/)（無料・キー不要）から取ります（名古屋駅の位置、3日先まで）。最初のあいさつの先頭で今日の天気（17時を過ぎたら明日）をつぶやき、質問にも使います。取れないときは天気なしで進めます。
- 基本情報（`piyo-basics.json`）は自動では更新しません。値段や営業時間が変わったら `lines` を直し、`checked` を確かめた日にします。
- メモの基準を変えたら `build_piyo.py` の `MEMO_VERSION`、まとめの基準を変えたら `GREETING_VERSION` を上げます。
- メモでは店舗名を「ぴよりんshop」と書くよう指示し、既知の誤字「ぴよりnshop」は生成結果と保存済みメモの本文で補正します。この表記修正では版を上げず、既存メモのAPI再生成を避けます。メモが変わった際のまとめ更新は従来どおりです。
- **その場で答える（料金なし）**：天気（名古屋。今日・明日・あさって・曜日・週末・1週間、雨・気温・日の入り・風・紫外線）、暦（祝日・連休・二十四節気・満月）、予定（「〇〇はいつから？」「これからのイベントは？」「いま買える限定は？」「今月の予定は？」）、基本情報（定番などの値段・お店・営業時間・消費期限・持ち帰り・予約・アレルギー・名前の由来・中身）、おみくじは、`piyo-extras.js` が手元のデータだけで答えます。Claude を呼ばないので、API キーが無くても答えます。聞き方が合わないもの・限定品の値段や場所・「〇〇について」の概要・理由やおすすめは、今までどおり Claude に聞きます。基本情報は `piyo-basics.json` に書いてある形のときだけ答えるので、書き方を大きく変えたら Claude に任せる形になります。
- **返事を流して出す**：Claude の返事は作りながら受け取り（ストリーム）、言い終わった文から順に出します（「ます」が「るぴよ」に変わって見えないよう、文の途中は出しません）。Web 検索だけは今までどおり、できあがってから出します。
- **記事・予定の札**：Claude には、答えに使ったメモと予定の id を最後に `[[参照:m3,e2]]` の形で書いてもらい、画面からは消して、返事の下に記事・予定の札（3つまで）を出します。押すと、ぴよの手前にリーダーが開きます。その場で答えた予定や「調べる」で読んだ記事も札にします。
- **ぴよの表情**：考え中はそわそわ、答えが出たらぴょんと跳ね、分からない・エラーのときはしょんぼりします。
- **あいさつ**：最初のあいさつの先頭に、時間帯のあいさつ（おはよう／こんにちは／こんばんは）と、近い予定の一言（「〇〇は今日まで」「明日から〇〇」「〇〇まであと◯日」、14日先まで）を足します。
- **ぴよを押すとひとこと**：チャットのぴよを押すと、手を振って、豆知識・二十四節気・次の満月や祝日・もうすぐの予定・明日の天気などを一言つぶやきます（同じ話は使い切るまで続けません）。
- **今日のおみくじ**：1日1回、質問の候補のいちばん右に出ます。結果は日付と端末ごとの種（localStorage `piyo-omikuji-seed`）で決まり、同じ日に何度聞いても同じです。
- **ちがうよ（まちがいを知らせる）**：ぴよの答え・あいさつ・ひとことの吹き出しの右下に、文が出終わってから小さな「ちがうよ」が出ます。押すと会話の中で「どこがちがう？」と聞き、札（答えがまちがい／質問がまちがい／情報が古い。あいさつは まとめがまちがい／情報が古い）を押すか、書いて送ると、この端末に記録して（localStorage `piyo-reports`、100件まで）、ぴよが確かめ直します。Mac の Claude はそのまま記事や Web で確かめ直し、API は料金がかかる前に「確かめ直す？」と聞きます。まちがいと言われた答えは会話の記憶（history）に印を付けます。候補から聞いた質問を「質問がまちがい」とした札は、この端末では出しません（`piyo-bad-suggest`）。記録は「ブックマーク」タブの下の「ぴよへの指摘」で見て、まとめてコピー・全部消すができます（コピーを Claude に渡すと、メモ・予定・候補を直す材料になります）。
- **住所に日本語が入った記事・MSN の記事も読む（2026-10-29）**：住所に日本語が入っていると、本文の取り込み・日付の読み取りで「'ascii' codec」のエラーになって読めませんでした。読むときだけ、その部分を %XX に書き直します。MSN の記事はページに中身が無く（ページが記事データを読み込んで出す）、読む画面が空でした。ページが読み込むのと同じ記事データ（assets.msn.com）から、題名・要約・画像・公開日を読みます（メディアの記事は要約と画像だけを保存するのは前と同じ）。中身の無いまま保存していた MSN の記事は読み直します。本文のファイル名や記事の住所は、もとのまま。
- **知識の間違いを防ぐ（2026-10-29）**：ぴよメモは1記事ずつ作ります（6記事ずつだと別の記事の話が混ざり、紅茶ぴよりんのセットに「ゴジラとのコラボ」が入った）。元の記事に無いカタカナの言葉を含む文はメモに入れません。「ぴよりn＋英字」「ぴよりン」は「ぴよりん」に直します。本文の取り込みと予定の取り出しは、丸数字（①など）を「1」にしません（「①10:00」が「110:00」になっていた）。まとめの「きょう」「あした」は月日にし、メモと予定に無い名前の候補は出しません。
- チャットとまとめでは、丁寧語を避け、すべての文末に「ぴよ」を付けるよう指示します。引用・URL・一覧を保護した文末補正も行いますが、安全に活用を変えられない「買えます」などは指示に任せます。まとめの版は3で、公開後の次の定期更新で作り直します。

## スマホだけの表示（読み込み画面・引っ張って更新・前回からの新着）

PC の表示は変えていません（どれも 620px 以下の幅だけ）。

- **読み込み画面**：アプリを開くと、ぴよが真ん中でぴょんぴょん跳ねます。最初のニュースを読み終えたら手を振って、ふわっと消えます（消え始めるまで最低3秒。読めなくても5秒で消えます）。前にアプリを開いていた時（閉じた・ほかのアプリへ移った時）から10分以内に開き直したときは、iPhone がページを覚えている間なので出しません。その時刻はブラウザ（localStorage `piyo-last-open`）にだけ保存します。
- **引っ張って更新**：いちばん上で下へ引いて離すと、ぴよが跳ねながらニュース・予定を読み直し、「新しい記事が◯件あったぴよ！」か「最新だぴよ！」と出します。公開ページを読み直すだけで、「更新」ボタン（GitHub Actions を動かす）とは別です。
- **前回からの新着**：前に開いたときに無かった記事（直近14日）に「前回から」の印を付け、一覧の上に「前回から◯件の新着」の帯を出します。帯を押すと新着だけを表示します。見た記事の記録はブラウザ（localStorage `piyo-seen`）にだけ保存し、アプリを閉じたとき・10分以上離れて戻ったときに「前回」を更新します。はじめて開いたときは印を付けません。
- **予定を iPhone のカレンダーへ**：予定をリーダーで開くと「iPhoneのカレンダーへ」のボタンが出ます（終わった予定には出ません）。終日の予定の .ics ファイルをその場で作って開きます。ホーム画面版でカレンダーに入るかは実機での確認が必要です。

## 「更新」ボタン（いますぐ更新）

ページ右上の「最終更新」の隣にある「更新」ボタン（スマホはタイトルの右の丸いボタン）で、GitHub Actions の「ぴよりんニュースを更新」を今すぐ実行できます。押すと実行の終わりまで待ち（1分ほど）、公開ページの最終更新の時刻が変わったら画面を読み直し、新しい記事の数（`meta.json` の `added`）を伝えます。

- はじめて押すと、合言葉（GitHubの細かい権限を指定できるトークン）の設定画面が出ます。リポジトリは `piyorin-news` だけ、Permissions の Actions を「Read and write」にして作り、貼り付けます。
- 合言葉はその端末のブラウザ（localStorage `piyo-run`）にだけ保存されます。ブックマーク同期の合言葉（gist用）とは別です。解除は「ブックマーク」タブの下にあるボタンから行います。
- 押すたびに予定の抽出と関連判定で Claude API が少し使われます。更新が同時に2つ走ることはありません（workflow の `concurrency`）。
- 合言葉が期限切れ・権限不足のときは、設定画面が理由つきでもう一度出ます。

## 更新の間隔を変える

`.github/workflows/update.yml` の `cron` を書き換えます（時刻は UTC）。

- 3時間ごと：`17 */3 * * *`
- 毎朝7時（日本時間）：`0 22 * * *`
